# 日志设计

日志实现约束见 `backend/AGENTS.md`；本文说明过程日志与诊断数据的协作方式。

## 目标与边界

- 每次 HTTP 请求结束输出一行过程摘要，基础字段与业务过程数据聚合输出；不把请求中途步骤变成事件流。
- 全服务使用 zap 与 `applog.L()` 全局 logger，不包 Logger 接口。默认输出 stdout，落盘与轮转由部署平台承担。
- panic 堆栈诊断是摘要之外的明确例外，诊断与摘要共用请求标识；`http.ErrAbortHandler` 原样向 net/http 传播。
- 不提供敏感值自动过滤。调用方不将密码、令牌明文或请求体放入过程数据，错误 op 只写静态上下文；链尾驱动原因原文保留用于排障，日志访问权限须相应管控。

## 分层协作

`backend/internal/kernel/applog` 零业务依赖，提供全局 logger 与标准 `context.Context` 中的请求级 kv 收集器：

```go
applog.Init(cfg)
logger := applog.L()
ctx := applog.NewCollector(ctx)
applog.Add(ctx, "wrong_count", applog.Int64(2))
fields := applog.Fields(ctx)
```

- 业务层只追加 kv，表现层的 ProcessLog 读取快照并输出摘要；kernel 不依赖 gin。
- 过程值限定 String/Int64/Float64/Bool/Time/Err；对象、切片等复杂值不进入收集器。
- 键用英文 snake_case。中间件字段是保留键，业务占用时丢弃并输出 debug 诊断；实际全集由 `applog` 维护。

## 请求标识同源

1. ProcessLog 在入口生成 16 hex 标识，不读取上游传入值。
2. 标识写入响应头 `X-Request-Id` 与 gin 请求值；键与存取统一在 `presentation/middleware/context.go`。
3. Bind/Handle、鉴权与恢复出口读取该值，经参数传给 response。response 不自行查找请求标识。
4. 所有错误体固定携带 `request_id`，摘要与 panic 诊断使用同一个值；成功响应体不增加该字段。

业务层日志收集器走标准 ctx，请求标识仅在表现层使用 gin 请求值，二者承担不同职责。

## 过程摘要

中间件顺序为 ProcessLog → ZapRecovery。主要字段：

| 字段 | 含义 |
|---|---|
| `request_id` | 与响应头、错误体同源的请求标识 |
| `method` / `route` | HTTP 方法与已匹配路由 |
| `status` / `latency_ms` / `client_ip` | 响应状态、耗时与客户端 IP |
| `user_id` | 已认证用户标识；未认证时省略 |
| `outcome` | ok / rejected / error / canceled |
| `public_error_code` | 归一化后实际对外语义，未知错误也记 internal_error |
| `error_chain` | 各项目错误的 code 与静态 op |
| `cause_type` / `cause` | 链尾标准库/第三方原因的类型与原文 |

- 2xx/3xx → Info，4xx → Warn，5xx → Error；请求上下文已结束时记录 canceled/Warn。
- `/healthz` 仅正常 200 降噪，探针失败与取消仍须记录。
- 框架级裸 handler 漏写响应时补 500；请求已取消不补写 JSON，避免把取消当成“正常 200”或“漏写失败”。状态字段可能仍是 writer 默认值，取消以 outcome 为准。
- 系统失败统一 `internal_error`，数据库、超时等归因经 op/cause 表达，不维护技术码。响应未知错误的归一化包装与原始 cause 都进入摘要，公开码与响应一致。

## 全服务日志与配置

日志配置来源是 `config.yaml` 的 `log` 段：format 为 text/json（默认 json），level 为 debug/info/warn/error（默认 info）。主进程加载配置后初始化 logger，启动、数据库组装与优雅停机诊断共用该 logger。

配置加载失败时 logger 尚未初始化，`config` 的致命加载错误仍由 stdlib log 输出。未调用 Init 时 L 返回 NOP logger，便于测试无需全局配置。

## 验证

- 收集器：受限值类型、保留键拒绝与快照行为。
- 中间件：级别映射、业务 kv 合并、健康探针降噪与失败可见。
- 错误出口：绑定失败、未知错误、panic、框架兜底的头/体/日志标识一致；公开码一致，cause 只进日志。
- 取消出口：不写 JSON、不触发漏响应兜底，仍留下 canceled 摘要。
