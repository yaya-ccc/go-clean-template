# backend/CONTEXT.md — 后端术语表

本文件只定义后端实现域概念；产品域术语见根 `CONTEXT.md`，实现约束见 `backend/AGENTS.md`。

## Language

### 账号与认证（实现侧）

**令牌对（Token Pair）**:
一次签发同时产出的 access token 与 refresh token。

**DTO**:
跨分层调用传递的命名数据类型，包括应用层的用例输入 Input、多值结果 Result，以及表现层的协议请求与响应视图。
应用层 DTO 不携带协议标签；单值产出和无产出不另造包装。
_Avoid_: 用例结果（旧称）、返回值对象、视图对象

### 过程日志

**过程日志**:
一次请求处理结束时输出的单行摘要，聚合请求标识、处理结果与业务过程数据。

**请求标识（Request ID）**:
服务端生成的单次请求关联标识，用于将响应头、错误响应体、过程日志与异常诊断对应起来。
_Avoid_: trace id、链路 id

### 错误体系

**错误码（Error Code）**:
对外失败语义的稳定机器标识，如 `email_taken`；每个码具有固定状态与用户文案，不承载原始故障文本。
_Avoid_: 错误号、数字码、错误枚举

**业务错误码（Business Error Code）**:
描述用例或领域失败语义的错误码，其意义取决于当前业务语境，而非底层技术类别。
_Avoid_: 内部事实码、模块内私有码

**系统错误（System Error）**:
数据库故障、依赖超时与其它系统性失败的统一对外语义；技术差异属于内部诊断原因，不构成独立公开码。
_Avoid_: 基础错误、数据库公开错误码、内部技术码

**语义转译（Semantic Translation）**:
用例将查询未命中等协作事实解释为当前业务失败语义的过程。
表现层将错误码渲染为状态与文案，不承担业务语义转译。

**仓储边界分类（Repository Boundary Classification）**:
仓储将明确可判定的存储失败归为业务语义，其余失败归为系统错误的过程。
_Avoid_: 防腐层（专指外部服务隔离）、错误归一化（仅覆盖系统失败）

### 表现层结构

**业务模块包（Module Package）**:
表现层按业务模块划分的包，承载本模块路由、handler、DTO 与协议转换。
_Avoid_: 业务部分、业务包

**协议公共件（HTTP Common）**:
表现层内不含业务语义的共享 HTTP 能力，如绑定、渲染、鉴权与路由组装。
_Avoid_: 系统部分、系统件、公共库

### 横切与持久化

**横切组件（Cross-cutting Component）**:
没有业务包 import 依赖、可由各分层共同使用的基础能力；错误码的纯标识符登记不属于业务逻辑承载。
_Avoid_: utils、common（无准入规则的大杂烩）

**防腐层（Anti-Corruption Layer）**:
以业务侧 port 和技术 adapter 隔离外部系统的结构，防止外部类型、错误与响应形状直通应用核心；不指自有数据仓储。
_Avoid_: ACL 网关、适配层（泛称）、把 mysql 的隔离也叫防腐层

**持久化模型（Persistence Model）**:
自有数据的存储形状，是持久化技术与领域模型之间的转换边界。
_Avoid_: model、entity、数据模型；PO 仅作代码标识符
